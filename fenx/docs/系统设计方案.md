# Fenx 跨平台代理用户/IP 合规监控平台设计方案

> 版本：v0.1（方案评审稿）  
> 目标：通过 `fenx_site` 写入前拦截与定期存量扫描，发现代理用户、关联联盟账号，并按代理范围治理重复注册/登录 IP。

> 重要边界：后台“正常用户/正常登录记录”在策略服务可用时不应出现新的重复事件，靠注册/登录写入前拦截实现；按业务要求，策略服务故障期间允许短时放行，因此需依赖告警和故障恢复后的补偿扫描。已经产生的历史日志不能被删除或篡改。违规记录进入隔离视图并保留审计证据，避免把治理误做成日志清除。

## 1. 设计结论

平台采用“实时拦截 + 只读采集 + 规则判定 + 可审计执行”的四段式流程：

1. 从 `kkud.user568531942` 按启用的 `daili` 读取用户资料。
2. 以手机号为主键，QQ、邮箱、用户名为辅助键，在 `fenx_site.users` 中查找关联账号；同时读取 `fenx_site.log_login` 补充成功登录 IP。
3. 在“同一代理”范围内，以注册 IP 和成功登录 IP 计算冲突，先生成待处理结果，再按代理配置的“阻断/禁用/删除业务账号/仅告警”策略执行。
4. 在 `fenx_site` 注册、登录写入前增加实时策略检查，重复请求直接拒绝，不写入新的业务注册/登录记录。

默认采用**写入前阻断**、**预览模式**和**禁用而非物理删除**。不得通过删除或篡改 `log_login` 等审计记录来掩盖已经发生的行为；历史异常应标记为违规/隔离并保留不可篡改证据。管理员确认后才允许按授权策略删除重复业务账号。所有外部写操作必须记录前后值、操作者、规则版本和任务批次。

## 3. 范围、假设与待确认项

### 3.1 本期范围

- 超级管理员、运营管理员、代理账号三种角色；若业务确认不需要运营管理员，可收敛为审计只读账号。

- 代理查看自己范围内的采集用户、关联账号、IP 冲突和处理结果。
- 管理员查看全部任务，并管理 `kkud` 用户 VIP 字段和 `fenx_site` 用户。
- 定时任务、手动任务、预览、确认执行、回滚/恢复（能恢复时）。

### 3.2 必须在开发前确认

1. `kkud.user568531942` 的实际主键、手机号、QQ、邮箱、注册时间、VIP 字段名称及类型。
2. `daili` 保存的是代理名称、代理 ID 还是混合值，是否存在大小写/空格差异。
3. `fenx_site.users` 的禁用状态枚举（源码显示 `status=2` 为正常，其他值包含未激活/锁定，但需以数据库约束为准）。
4. 是否只治理“同一代理”内的 IP，还是所有代理之间也禁止重复；本方案默认前者。
5. “一个用户只能在一个 IP 注册或登录一次”中的“一次”是永久、自然日、滚动 24 小时还是可配置窗口。本方案默认永久历史判定，并提供时间窗口开关。
6. 手机号为空或多人共用手机号时，是否允许以 QQ/邮箱进行低置信度关联；默认需要人工确认。

上线前用脱敏抽样数据验证字段映射，禁止直接在生产执行未知字段的 `UPDATE/DELETE`。

## 4. 总体架构

```text
Vue 3 管理端
      │ HTTPS + JWT
Go API 服务 ── RBAC / 审计 / 限流 / 字段脱敏
      ├── PostgreSQL（平台配置、快照、冲突、审计）
      ├── Redis（队列、分布式锁、任务进度、短期缓存）
      ├── KKUD MySQL Adapter（建议只读账号；VIP 修改走受控命令）
      └── Fenx MySQL Adapter（查询/禁用/删除/编辑，按权限）
                 │
          Scheduler + Worker
```

服务拆分建议：

- `api`：认证、代理配置、查询、预览和确认执行。
- `worker`：采集、关联、冲突计算、执行外部写操作。
- `scheduler`：按任务周期投递 Redis 队列；多实例用锁保证单次执行。
- `adapter`：封装两套旧 MySQL 的 SQL、字段映射、事务和连接健康检查。
- `audit`：不可变审计事件，包含任务批次和操作前后摘要。

### 4.1 `current_dir` 接入方式

在旧 PHP 系统的注册和登录成功分支增加内部 HTTPS 调用（或同机 Unix socket 调用）到 Go 的 `decision` 接口：

1. PHP 先提交规范化手机号、账号 ID、代理标识、客户端 IP、动作类型和请求幂等键。
2. Go 服务在事务/分布式锁下检查该代理 IP 是否已被其他账号占用，返回 `allow`、`deny_duplicate_ip` 或 `review`。
3. 只有 `allow` 才继续原有 `users` 写入、`loginip` 更新和 `log_login` 成功记录；`deny` 返回明确业务提示并不写入成功事件。
4. Go 服务自身记录每次决策和拒绝原因；按当前业务要求，PHP 调用失败时默认 **fail-open（放行原有注册/登录流程）**，但必须记录 `decision_service_unavailable`、写入告警和失败计数。连续失败达到阈值、超过配置的最大降级时长或检测到异常流量时，自动切换为人工审核/强制拦截，并通知超级管理员；该模式通过环境变量和后台开关配置，不能静默变更。

该接入点解决“后台不再新增重复记录”的根因；定时任务只负责发现历史数据、处理存量账号和复核实时拦截遗漏。

### 4.2 `current_dir` 具体改动文件清单

| 文件 | 修改位置 | 修改职责 |
|---|---|---|
| `application/controller/index.ctl.php` | `post_register()`、`postlogin()` | 注册写入前、登录成功写入前调用 Go 决策接口；命中重复 IP 时提前返回，不执行原有写入、`loginip` 更新和成功 `login_log` 记录 |
| `application/controller/oauth/qq.ctl.php` | `userlogin()` | QQ 绑定账号登录路径增加相同拦截，避免绕过普通账号登录检查 |
| `application/models/index/user.mod.php` | `post_register()`、`update_user_login()`、`login_log()` | 增加统一保护和参数校验，防止其他控制器直接调用模型绕过拦截；失败登录日志与成功登录日志分开处理 |
| `application/api/api_user.php` | `set_login_seesion()` | 增加会话创建的最后一道状态检查，账号被禁用/隔离时不得继续建立有效会话 |
| `library/function/system.fun.php` | `get_ip()` | 统一 IP 获取和规范化；仅在配置可信反向代理后解析 `X-Forwarded-For`，不能直接信任客户端请求头 |
| `www/config.php` | 全局配置区 | 增加 Go 决策服务地址、请求超时、`fail-open` 开关、失败阈值和降级时长；真实密钥放环境变量，不写入源码 |

推荐调用顺序：

```text
接收请求 → 规范化 IP/手机号 → 调用 Go 决策接口
  ├─ allow：继续原有 users 写入/更新和成功日志
  ├─ deny_duplicate_ip：返回业务提示，不执行成功写入
  └─ service_error：按配置 fail-open 放行，同时记录故障事件和告警
```

普通密码登录和 QQ 登录必须覆盖；管理员代登录、后台内部跳转等路径不应被误当作用户注册/登录事件，但仍需保留原有权限校验和审计。

当前实现状态：已在 `current_dir/library/function/fenx_guard.fun.php` 提供 HMAC 请求客户端，并接入 `index.ctl.php` 的普通注册/密码登录、`oauth/qq.ctl.php` 的 QQ 登录；Go 端 `/api/v1/decision` 已校验 `X-Fenx-Signature`，并以 PostgreSQL `ip_claims`（模型 `IPClaim`）记录“代理 + IP + 动作 + 账号”占用。PHP 调用失败按 `fail-open` 放行并写入 PHP 错误日志；生产环境还需补充集中式告警和失败阈值自动切换。当前后端另提供 `POST /api/v1/connections/test`，通过根目录 `.env` 的 MySQL DSN 检查 `kkud` 与 `fenx_site` 连通性。

## 6. 核心业务流程

### 6.1 代理配置

代理账号首次登录后填写“代理名称”，系统对名称做 Unicode 规范化、去首尾空格并保留原始显示名。管理员审核后才能启用监控。每个代理拥有：

- `agent_key`：内部稳定 ID，不能以显示名作为关联主键。
- `source_value`：用于匹配 `kkud.daili` 的精确值，可配置多个别名。
- 监控周期：5 分钟至 24 小时，默认 30 分钟。
- 时间范围：全量、最近 N 天、从上次游标增量。
- 冲突策略：仅告警、禁用、删除；可分别设置“注册 IP冲突”和“登录 IP冲突”。
- 保留规则：冲突时保留最早注册、最近活跃、VIP 或人工指定账号。

### 6.2 采集任务

1. Scheduler 为每个启用任务创建 `run_id`，用 Redis 锁 `monitor:{task_id}` 防止重复执行。
2. Adapter 只查询需要的字段，按主键/更新时间分页，禁止无条件加载整表。
3. 将原始记录写入 `kkud_user_snapshots`（字段 JSONB + 规范化索引），保存 `source_updated_at` 和哈希，实现幂等。
4. 任务记录读取数量、游标、耗时、错误和重试次数；网络失败采用指数退避，超过阈值转人工处理。

### 6.3 跨库关联

字段规范化：手机号去空格和短横线并校验国家码；QQ/邮箱转小写、去空格；用户名按配置决定是否大小写不敏感；IP 统一压缩 IPv6 表示，识别 `unknown`、内网地址和代理头异常。

关联优先级：

1. 手机号完全匹配：高置信度。
2. 手机号 + QQ/邮箱同时匹配：高置信度并用于消歧。
3. QQ 或邮箱单字段匹配：中置信度，默认只进入待确认队列。
4. 用户名匹配：低置信度，不能自动执行删除。

同一 kkud 用户匹配到多个 fenx 账号时，生成 `ambiguous` 结果，不执行自动治理。所有匹配保存命中的字段、置信度、规则版本和脱敏摘要。

### 6.4 IP 冲突判定

默认冲突范围为同一 `agent_id`：

- 注册冲突：两个或以上关联账号的 `users.regip` 相同且有效。
- 登录冲突：两个或以上关联账号的 `users.loginip` 相同，或 `log_login` 中成功记录 `status=1` 的 IP 相同。
- 实时占用：同一代理下注册与登录共用 IP 占用集合；账号 A 注册后，账号 B 不能再以该 IP 登录，避免按动作拆分造成绕过；同一账号自己的后续登录允许复用原 IP。
- 账号自身注册 IP 与登录 IP 相同不算冲突；同一 IP 的失败登录不触发删除。
- 空 IP、内网 IP、解析失败 IP 只告警，不进入自动执行集合。
- 可选时间窗口：`permanent`、`rolling_24h`、`calendar_day`。

冲突记录必须包含：代理、IP、账号列表、来源字段（注册/当前登录/登录日志）、首次/最近时间、匹配依据、建议保留账号、风险等级。

建议默认保留排序（可配置）：

1. 人工锁定/白名单账号。
2. VIP 账号（仅作为建议，管理员可关闭）。
3. 最早注册且状态正常的账号。
4. 最近有成功登录且资料完整的账号。
5. 其余账号进入处理集合。

### 6.5 处理策略与安全闸门

- **实时写入前拦截（首选）**：在 `current_dir` 的注册处理和登录成功处理之前调用平台策略 API，使用 `agent_id + normalized_ip + action(register|login)` 做幂等判定；命中已占用 IP 时返回业务拒绝，不执行 `users` 写入、`loginip` 更新或成功登录日志追加。Redis 只用于短期锁，最终占用关系必须落 PostgreSQL/受控索引，避免缓存丢失导致绕过。
- **历史记录处理边界**：不能删除或修改 `fenx_site.log_login`、注册 IP、登录 IP 等审计证据以隐藏重复行为。历史异常应写入冲突/隔离表；“正常记录”视图仅展示当前有效账号，管理员可通过独立的违规审计视图查询原始记录和完整证据链。
- **仅告警**：创建冲突并通知，不改外部数据。
- **禁用**：使用 fenx 的状态字段将账号设为锁定/禁用，并可吊销在线会话；先保存原状态。
- **删除业务账号**：执行前必须二次确认、输入冲突 IP 或任务确认码；只删除经授权确认的重复业务账号及其在线会话，不删除 `log_login` 等审计记录；先归档账号关键字段和关联表影响范围，再在单账号事务中删除。
- 代理账号不能绕过管理员设置的最大批量数、最小置信度和白名单。
- 删除失败不自动重试写操作；转为“部分成功”，等待人工重试。
- 所有批量操作提供“撤销禁用”；物理删除只提供从归档恢复到隔离表的人工流程，不能承诺无条件恢复。若业务方坚持清理历史展示，应通过带权限的“违规隔离视图”实现，不得物理抹除审计数据。

|---|---|---|
| `platform_users` | `id, username, password_hash, role, agent_id, status, last_login_ip` | 平台账号；密码使用 Argon2id/bcrypt |
| `agents` | `id, display_name, source_values, enabled, policy_json` | 代理配置和策略版本 |
| `monitor_tasks` | `id, agent_id, interval_sec, cursor, enabled, next_run_at` | 监控任务 |
| `sync_runs` | `id, task_id, status, started_at, ended_at, counters, error` | 任务批次和进度 |
| `kkud_user_snapshots` | `id, source_pk, agent_value, normalized_mobile, normalized_qq, data_jsonb, data_hash` | kkud 脱敏/原始快照分层存储 |
| `fenx_user_refs` | `fenx_uid, username, mobile_hash, source_seen_at` | fenx 账号索引，不重复保存不必要的明文 |
| `user_matches` | `run_id, kkud_snapshot_id, fenx_uid, confidence, matched_fields, state` | 关联结果 |
| `ip_conflicts` | `agent_id, ip, conflict_type, window, risk, status, winner_uid` | 冲突集合 |
| `conflict_members` | `conflict_id, fenx_uid, reg_ip, login_ip, evidence_jsonb` | 冲突账号明细 |
| `action_jobs` | `conflict_id, action, status, before_jsonb, after_jsonb, idempotency_key` | 外部写操作队列 |
| `audit_events` | `actor_id, action, target, request_id, run_id, before_hash, after_hash, created_at` | 追加写审计 |
| `allowlist` | `agent_id, fenx_uid, ip, reason, expires_at` | 白名单，必须有过期时间 |

索引建议：`agents(source_values gin)`, `kkud_user_snapshots(agent_id, normalized_mobile)`, `user_matches(fenx_uid)`, `ip_conflicts(agent_id, ip, status)`, `audit_events(created_at, actor_id)`。手机号、邮箱等 PII 默认加密或哈希检索，页面按角色脱敏展示。

## 8. 外部数据库适配与写操作

### 8.1 连接配置

外连 MySQL（kkud / fenx_site）的连接配置**不放在环境变量或 .env 中**，由超级管理员在后台「系统设置」页维护，保存在平台库 `sys_config` 表（键：`kkud_host/kkud_port/kkud_name/kkud_user/kkud_password`，fenx 同理；`GET /api/v1/settings/external-db` 永不回显密码，`PUT` 时空 password 表示保持原值）。保存后旧 DSN 的连接池立即失效重建；所有采集、关联、检测、冲突执行、VIP、用户管理操作在每次执行前从 sys_config 解析连接。首次引导可用环境变量 `KKUD_DB_*` / `FENX_DB_*` 兜底（不在 .env.example 中列出），sys_config 配置齐全后优先使用 sys_config。

生产环境建议：不同用途使用不同账号；采集账号只授予 `SELECT`，VIP 修改账号只授予目标表的指定列 `UPDATE`，fenx 运维账号只授予明确的用户表和会话表权限；限制来源 IP、启用 TLS（若服务端支持）、设置连接超时和最大连接数。

### 8.2 SQL 适配层

Go 代码通过接口隔离具体字段：

```go
type KKUDUser struct {
    SourceID string
    Agent    string
    Mobile   string
    QQ       string
    Email    string
    RegTime  time.Time
    VIP      any
}

type FenxUserRepository interface {
    FindCandidates(ctx context.Context, key IdentityKey) ([]FenxUser, error)
    ListSuccessfulLoginIPs(ctx context.Context, uid int64) ([]string, error)
    Disable(ctx context.Context, uid int64, reason string) error
    Delete(ctx context.Context, uid int64, reason string) error
    Update(ctx context.Context, uid int64, patch UserPatch) error
}
```

实际字段、状态值、级联表和删除约束通过启动时 schema 检查与人工确认配置，不允许把表名/列名直接拼接用户输入。

## 9. API 设计（摘要）

统一前缀 `/api/v1`，返回 `{code, message, data, request_id}`；列表使用游标分页。

认证：`POST /auth/login`、`POST /auth/refresh`、`POST /auth/logout`、`POST /auth/change-password`。当前登录已支持环境变量超级管理员和 PostgreSQL `platform_users` 账号；`GET/POST /users` 仅超级管理员可用，代理账号密码使用 bcrypt 哈希保存。

代理与任务：`GET/POST/PATCH /agents`、`GET/POST/PATCH /monitor-tasks`、`POST /monitor-tasks/{id}/run`、`GET /sync-runs`（最近 100 次运行）。手动运行会按代理的 `source_values` 解析多个 `daili` 值，查询 `kkud.user568531942`，并写入 `sync_runs` 与 `kkud_user_snapshots`；快照字段采用大小写不敏感映射，兼容 `id/uid`、`mobile/phone`、`qq`、`email` 等常见命名，未知字段完整保存在 JSONB 中。

数据与关联：`GET /kkud/users`、`GET /fenx/users`、`GET /matches`、`GET /conflicts`、`GET /conflicts/{id}`。当前实现的 `GET /kkud/snapshots` 支持 `mobile`、`agent_value`、`limit` 筛选并返回最近快照；`GET /matches` 返回最近 200 条手机号优先的只读关联结果，低置信度 QQ/邮箱命中标记为 `review`，不会自动修改外部数据库。

执行：`POST /conflicts/{id}/preview`、`POST /conflicts/{id}/actions`、`POST /actions/{id}/retry`、`POST /actions/{id}/undo-disable`。

管理员专用：`PATCH /kkud/users/{source_id}/vip`、`PATCH/DELETE /fenx/users/{uid}`、`GET /audit-events`、`POST /connections/test`。

高风险接口要求 `Idempotency-Key`、二次确认 token、CSRF 防护（若使用 cookie refresh token）和审计事件。错误响应不得包含 SQL、密码、完整手机号或连接串。

## 10. Vue 侧边栏信息架构与 UI 规范

采用桌面优先的后台壳层，同时兼容 375px 移动宽度：固定侧边栏 + 顶部上下文栏 + 单一主内容区；移动端侧边栏折叠为抽屉，不能出现横向滚动。

### 10.1 超级管理员菜单

- 总览：任务健康、待处理冲突、近 24 小时动作、连接状态。
- 代理与任务：代理列表、任务配置、运行记录。
- kkud 用户：筛选、详情、VIP 开通、快照。
- fenx 用户：搜索、编辑、禁用、删除、会话/IP 查看。
- IP 冲突中心：按代理/IP/风险/状态筛选，预览与批量执行。
- 审计与系统：操作日志、连接配置、策略模板、白名单、系统健康。

### 10.2 代理菜单

- 我的概览：本代理统计和最近一次同步。
- 我的用户：kkud 用户及关联 fenx 账号。
- 冲突处理：冲突详情、策略设置、预览、允许范围内的执行。
- 任务记录：运行状态、错误、重试。
- 账号设置：代理名称、密码、二次验证。

### 10.3 关键页面交互

- 冲突详情使用“证据时间线”：kkud 注册 → fenx 注册 → 成功登录 → 判定 → 执行。
- 删除/禁用为危险操作，必须显示影响账号数、IP、匹配依据和恢复能力，并要求明确确认。
- 表格支持列配置、脱敏开关、导出权限控制；长列表虚拟滚动。
- 所有异步任务显示进度、最后更新时间、重试入口和可读错误原因。
- 空状态提供下一步操作，表单使用可见标签、字段级校验和提交中状态。

### 10.4 视觉与可访问性基线

- 建议使用“深海军蓝侧栏 + 中性浅色内容区 + 靛蓝主色 + 语义红/橙/绿”令牌，暗色模式单独校验对比度。
- 使用 Lucide/Heroicons 等统一 SVG 图标，不使用 emoji 作为结构图标。
- 8px 间距节奏，正文至少 14–16px，交互目标不小于 44×44px，键盘可操作并保留可见 focus ring。
- 动画控制在 150–300ms，支持 `prefers-reduced-motion`；颜色不是唯一状态表达方式，必须同时有文本/图标。

## 11. 定时任务、可靠性与可观测性

- Redis Streams 或可靠队列承载 `collect → match → detect → apply` 四类消息。
- 每个任务使用租约锁、幂等键和 checkpoint；服务重启后可从最后游标继续。
- 指标：成功/失败任务数、采集延迟、匹配率、歧义率、冲突数、动作成功率、外部 DB 延迟。
- 日志结构化输出 `request_id/run_id/task_id/agent_id`，敏感字段哈希化；告警发送前脱敏。
- 连接失败、字段变化、权限不足、删除约束失败分别归类，避免无限重试。

## 12. 安全与隐私

- 强制 HTTPS、CSP、HSTS、CSRF、防暴力登录、登录 IP/设备审计和管理员二次验证。
- JWT access token 短时有效；refresh token 哈希存储并支持单设备/全局撤销。
- PII 最小化：手机号页面默认 `138****1234`，导出和接口按权限返回；快照设置保留期限并支持清理。
- 任何物理删除前保留加密归档、审批人和工单号；高风险操作支持双人复核。
- 与业务方确认用户协议、隐私政策、数据处理授权和跨系统数据共享边界；若无法确认，先只做告警不做自动删除。

## 13. 测试与验收标准

1. 单元测试：手机号/QQ/邮箱规范化、IP 规范化、置信度、胜出规则、时间窗口。
2. 集成测试：MySQL 只读采集、游标续跑、字段缺失、超时重试、PostgreSQL 事务、Redis 锁。
3. 回放测试：使用脱敏快照验证同 IP 多账号、跨代理同 IP、空 IP、歧义匹配、VIP/白名单。
4. 安全测试：JWT 撤销、越权访问、SQL 注入、批量接口限流、审计不可篡改、敏感字段脱敏。
5. 运行验收：连续运行 24 小时无重复批次；失败任务可重试；预览与执行结果一致；禁用可撤销；删除有完整证据链。

## 14. 分阶段实施

### Phase 0：字段确认与只读探针

建立最小权限账号，确认三张核心表字段、状态枚举、删除级联关系；实现连接测试和只读样本导出。

### Phase 1：平台骨架与监控

完成 Go/GORM/PostgreSQL/Redis、JWT/RBAC、代理和任务配置、快照、关联、冲突只读页面；默认仅告警。

### Phase 2：预览与禁用

加入策略、白名单、预览、审批、禁用、会话吊销和撤销；用脱敏回放数据压测。

加入 kkud VIP、fenx 用户编辑/删除、审计导出、连接健康、告警与报表。

仅在业务方确认法律和恢复要求后开启，设置批量上限、双人复核和分批灰度；持续保留只读/禁用作为安全回退。
